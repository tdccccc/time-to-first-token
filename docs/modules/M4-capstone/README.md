# M4 · 综合项目：跨芯片推理优化报告

**本章目标。** 复用第 30 章同一份报告初稿和原始记录，补齐条件编号、证据等级、重复运行和优化后验收，形成可复现、能明确指出缺口的跨芯片报告。

> **状态**：这里给交付框架与 D 级教学算例，不是 GPU/NPU 实测。环境、评测和性能表沿用第 30 章，不另写平行报告。统一口径见[跨章节实验约定](../../experiments.md)；缺设备的项保留待验证，不用算例填实测格子。

## 问题与交付

> 同一模型、同一评测集、同一负载，在 NVIDIA 与至少一种国产芯片上，性能、精度和稳定性差异是什么？哪些解释有对照证据，哪些只能列为候选？

评价依据是数据可追溯和归因可证伪，不要求证明某一方胜出。第 30 章的初稿是本章起点，最终交付同一份主报告、原始数据、复现命令、带负载/SLO/成本边界的选型结论，以及至少一项负面结果。

前置：第一部分的度量与压测、第二部分的服务部署；第三部分至少完成一个算子参考实验，或第四部分跑通过服务。第 29 章无 NPU 时只完成迁移计划，不能当作已成功移植的前置成绩。缺一边硬件仍可完成框架、条件和脚本，结果保持待测。

## 实验条件与范围

冻结条件后再跑。软件或硬件升级不会抹掉历史结果，但旧数据只对原条件有效，新环境要新建 conditions_id 并重测。

| 维度 | 必须记录/控制 | 记录方式 | 最少覆盖 |
|---|---|---|---|
| 模型 | 权重 revision/hash、量化格式、tokenizer 与 prompt 模板 | 配置正本及哈希 | 一个主模型 |
| 硬件 | 型号、数量、显存、互联、宿主驱动/固件 | 设备输出、拓扑、采集日期；容器不锁宿主 | 两边各一套 |
| 软件 | 实际 runtime/SDK、框架、引擎、插件和加速库 | 包清单、镜像 digest；nvidia-smi CUDA 是驱动上限 | 两边各一份 |
| 服务 | 并行度、上下文、batch/图/缓存参数 | 完整启动命令 | 两边各一份 |
| 负载 | 输入/输出长度及来源、采样、并发模型 | 固定输入/种子和原始记录 | 至少三级并发 |
| 测量 | 预热、正式请求数、重复数、超时、分位算法 | 正式请求数远大于并发 | 每格可回溯 |

| 实验 | 固定 | 变化 | 回答的问题 |
|---|---|---|---|
| E1 基线 | 模型、负载和可比引擎条件 | 硬件及对应实现 | 同条件结果差多少 |
| E2 并发扫描 | 模型、负载、硬件 | 并发 | 拐点、饱和和 SLO 边界 |
| E3 精度回归 | sample_id、判分、采样和预设退化门槛 | 平台/实现 | 配对质量差异与区间是否过门槛 |
| E4 算子归因 | 版本、阶段、形状 | profiling 采集 | 实际路径、耗时与回退证据 |
| E5 单点优化 | 其他条件、同组质量数据和门槛 | 一个优化因素、新 conditions_id | 重跑正确性、质量、路径、性能，决定保留/回滚 |

条件不同的结果可以并列，但不能直接相减后宣称“提升 X%”。固定 max_tokens 只是生成上限，实际长度、EOS/截断和 token 来源都要记录。20 请求只用于 C=1/4 的 mock 自查，不用于高并发性能结论。

## 数据契约

复用第 30 章原始文件，用 `平台-实验-并发-重复号` 标识记录；不要将三轮中最好一次当唯一结果。

| 字段 | 含义 | 缺失时怎么办 |
|---|---|---|
| `test_id` / `run_id` | 实验、并发与重复号 | 无编号的数据不进入主结论 |
| `status` | measured / pending / failed / invalid | pending 不填实测数字 |
| `conditions_id` | 指向环境、模型和负载正本 | 条件不全只进附录 |
| `raw_path` | 原始 JSON/CSV | 每个真实结果可回溯 |
| `requests` | 总数、成功、失败、超时 | 分母和时间窗口不清不得报吞吐 |
| `ttft_ms` / `itl_ms` | 分位数、样本量、chunk/token 口径 | 样本不足或估算明确标注 |
| `throughput` | 单位、成功口径、窗口、token 来源 | 请求/秒与 token/秒不混 |
| `accuracy` | sample_id 配对数据、指标、预设退化与区间 | 未测或区间跨门槛写证据不足 |
| `evidence` | 日志、profiler、代码标识与 E5 四项重测 | 无对照的机制只能列候选 |

真实报告只引用可追溯的数据行；下面的 D 级算例单独用于教学，不属于 measured 原始记录。质量门槛先写定，“不显著”不等于质量通过，优化前的 E3 也不替代优化后的质量回归。

## 证据等级与归因

| 等级 | 证据 | 可以怎么写 |
|---|---|---|
| A | 同条件、多次运行的原始数据与日志 | “在本实验条件下，测得……” |
| B | 同条件真实单次运行、重复不足 | “单次测得……，重复性待补测” |
| C | 官方资料、论文或外部报告 | “来源 X 宣称……”并列条件 |
| D | 算例、估算、推断、未运行 | “假设/估算……，待验证” |
| X | 口径不一致、不可复现 | 不用于性能结论，只记录原因 |

归因沿“现象 → 定位 → 候选机制 → 同条件对照 → 边界”走。没有第 4 步只能写“相关，未确认因果”。profiling 占比不是因果证明；设备时间占比也不是尾延迟占比。对照须重复，并确认正确性、质量和路径没有同时改变。

## 一份算例报告：从条件表到结论

> **算例声明**：本节所有数值、条件和假设定位均为 D 级教学演示，没有 raw_path 对应的真实运行，没有 NPU 实测。不能先标假设的 B 级再靠总声明免责。

**条件表（D 级）。** 真实报告继续使用第 30 章已有条件正本，以下仅展示字段，不构造虚假的兼容版本组合。

| 维度 | 平台 A（NVIDIA） | 平台 B（Ascend） |
|---|---|---|
| 硬件（假设） | A100 80GB，单卡 | 910B 64GB，单卡 |
| 软件栈 | 宿主驱动、实际 runtime、PyTorch、Triton、vLLM：待填写/核验 | HDK、CANN/Ops/NNAL、TorchNPU、引擎/插件：待填写/核验 |
| 模型 | Llama-3.1-8B-Instruct，FP16，revision/hash 待填 | 同一权重、tokenizer 与模板 |
| 服务 | 完整启动命令待填，不能用省略号复现 | 对应命令、插件和图配置待填 |
| 负载 | 固定 Sky prompt，输入 token 数待 tokenizer 实测；输出上限 128，并发 1/8/32，每级 1024 请求 | 同 A；实际长度/来源分别记录 |
| 评测（假设） | MMLU 子集 1000 题，5-shot；sample_id、判分和门槛待填 | 同 A |
| 证据级 | D（未运行） | D（未运行） |

**结果表（全部 D 级）。** 这些数字只演示计算和呈现格式，不是下方命令产生的结果。

| 实验 | 指标 | 平台 A | 平台 B | B/A 或差异 | 证据级 |
|---|---|---:|---:|---:|---|
| E1，C=1 | TTFT p50/p95（ms） | 180/220 | 260/340 | 1.44/1.55 | D |
| E1，C=1 | ITL p50/p95（ms） | 28/40 | 35/55 | 1.25/1.38 | D |
| E2，C=32 | 吞吐（token/s） | 620 | 430 | 0.69 | D |
| E2，C=32 | TTFT p95（ms） | 900 | 1500 | 1.67 | D |
| E2，C=32 | ITL p95（ms） | 120 | 180 | 1.50 | D |
| E3 | accuracy | 85.0% | 84.2% | -0.8 pp | D |
| E3 | PPL（另行取得 NLL 时） | 6.82 | 6.95 | +1.9% | D |

**摘要（D 级算例）。** 假设 C=32 得到上述数据，则 TTFT p95、ITL p95 的差异为 +67%、+50%，吞吐为 -31%。accuracy 的 -0.8 pp 还需要逐题配对结果与预设退化门槛，不能宣布是噪声或质量通过。TTFT 的候选原因是 eager 下发/调度，ITL 的候选是激活实现或排队，均未确认因果。假设单点实验出现 180→140 ms，也须同条件多次运行，并重跑正确性、同组质量和路径命中后，才决定优化是否有效。本算例不提供芯片选型结论。

**归因记录（全部 D 级）。** 表格完整不代表机制已验证。

| 假设现象 | 假设定位 | 候选机制 | 计划对照/待验证 | 边界 |
|---|---|---|---|---|
| ITL p95 180/120 ms | 激活占设备时间 12%/3%，不是尾延迟占比 | 通用激活路径或排队，未确认因果 | 单点替换并重测；140 ms 仅作 D 级格式演示 | C=32；正确性、质量、路径和重复性待测 |
| TTFT p95 1500/900 ms | prefill 启动次数多 18% | 未开图时 eager 下发较多；不声称关闭图仍触发图重编 | 开图、固定形状再对照；1200 ms 是 D 级估算 | 版本、形状、质量门槛待核验 |

**局限与下一步。** 两边均未运行，不是“各跑一次”。取得原始数据后至少重复三轮；保存配对质量数据并先定门槛；实际采一次路径/显存/KV 证据；对图配置做单点对照。每项写所需设备、版本、入口和触发条件。

**命令形式。** 在目标环境执行，不是算例数字的来源；两边用同一输入和评测，文件与条件编号分别登记。固定 Sky prompt 不是 512 tokens。MMLU 命令不自动生成“1000 题子集”或 PPL：子集保存样本 ID，NLL/PPL 另行评测，API 参数按安装版本核验。

```bash
python3 docs/modules/M0-foundations/scripts/bench_openai.py --base-url http://localhost:8000 \
  --model meta-llama/Llama-3.1-8B-Instruct --prompt 'Explain why the sky is blue.' \
  --max-tokens 128 --concurrency 1 8 32 --requests 1024 \
  --test-id A-E2-r1 --conditions-id A-fp16-v1 --output A-E2.json

lm_eval --model local-completions \
  --model_args base_url=http://localhost:8000/v1/completions,model=meta-llama/Llama-3.1-8B-Instruct \
  --tasks mmlu --num_fewshot 5 --output_path A-E3.json
```

## 交付结构与验收门槛

在第 30 章同一份初稿上补：摘要、条件编号和原始记录、真实结果与分布、已验证/候选归因、E5 优化记录、复现步骤、局限。环境表与覆盖/迁移正本引用而非重写。

- 每个真实性能数字追得到 raw_path 和 conditions_id，不挑最好一次。
- 至少三级并发覆盖低负载、拐点附近和拐点后；失败/超时与过载边界保留。
- TTFT/ITL 分开，分位数、样本量、token/流式块口径明确。
- 每次 E5 后重跑**正确性、同组质量、实际路径和性能**。四项满足预设门槛，并有同条件 before/after 和重复结果才写“优化有效”；否则待验证或回滚。
- 两平台和 E5 前后复用同一 sample_id/判分/采样，保存配对差异、区间和预设最大退化；“不显著”不是通过。
- 指出至少一项证据不足的结论与补测条件，保留至少一个负面结果。
- 历史数字对原条件有效，但不能当成新版本/新负载结果，旧数据不覆盖。

## 风险与待补测

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 版本不兼容 | 安装成功却启动失败/路径未命中 | 核对宿主和用户态整组，先冒烟 |
| 负载不一致 | 输入/输出长度或 token 来源不同 | 同一输入/种子，实际长度分别留档 |
| 只测性能 | 改算子/量化/图后未重跑质量 | E5 四项验收，不以旧 E3 替代 |
| 只跑一次 | 波动大于组间差异 | 重复并报告区间，不挑最好值 |
| 归因过度 | 只看 profiling 占比就下结论 | 实际单点对照，未验证仍列候选 |
| 缺少国产设备 | 无 NPU 或仅短期借用 | 先做框架和 GPU 基线，NPU 项待验证 |
| 数据不可追溯 | 找不到原始记录/条件 | 不进入主结论 |

待补测任务写“缺什么环境、补哪格、入口是什么、验收标准是什么”。例如 Ascend E5 待测：锁定型号与 CANN/插件版本，baseline 和单点候选复用同组输入，重复三轮，分别保存正确性、质量、路径和性能证据。
