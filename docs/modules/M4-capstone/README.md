# M4 · 综合项目：跨芯片推理优化报告

> **状态**：交付框架已确定；实验结果需要用同一套条件实际跑出来后填入。没有跑过的格子写「待补测」，未核实的外部数字标来源，不能用厂商宣称或估算值冒充实测。

## 问题与交付

本章要回答的问题：

> 同一模型、同一评测集、同一负载，在 NVIDIA GPU 与至少一种国产芯片上，性能、精度与稳定性差异是什么？哪些差异能被证据归因到算子、显存、调度或通信，哪些只能标为版本或环境未知？

评价依据是可复现的数据和证据归因，而不是必须提出新算法或证明某一方胜出。把同一件事在两套硬件上按同一口径做两遍，并让第三个人能根据你留下的材料复现实验或指出缺口。

最终产出是一份报告加一组可复现材料：

1. **主报告**：结论、实验设置、结果、归因、优化记录、复现步骤、局限。
2. **原始数据**：每档并发的请求级记录或汇总文件，文件名能对应到实验编号。
3. **可复现脚本**：环境检查、启动、压测、导出和校验命令。
4. **选型结论**：写清负载、延迟预算、成本和适用边界。
5. **负面结果**：至少一个“改了但没变快”或“换了硬件但没达到预期”的案例，并有排查证据。

前置能力：第一部分会用 Roofline 和压测脚本；第二部分部署过 vLLM 或 SGLang；第三、第四部分至少完成一个自写 kernel，或在 Ascend 上跑通过一次推理服务。缺少一边硬件时仍可完成报告框架、数据契约和复现脚本，但结果列不能填推测值。

## 实验条件与范围

先冻结实验条件，再开始跑。不要在换过驱动、权重或引擎版本之后，仍把新旧数字放进同一张对比表。

| 维度 | 必须固定 | 记录方式 | 最少覆盖 |
|---|---|---|---|
| 模型 | 权重仓库、修订号、量化格式、tokenizer | 权重文件哈希或仓库 commit | 一个主模型 |
| 硬件 | GPU/NPU 型号、数量、显存、互联方式 | `nvidia-smi`/`npu-smi` 输出、节点拓扑 | 两边各一套 |
| 软件 | 驱动、固件、SDK、PyTorch、推理引擎、插件版本 | 版本清单文件 + 采集日期 | 两边各一份 |
| 服务 | 启动命令、并行度、最大上下文、batch 相关参数 | 完整命令，不用省略号 | 两边各一份 |
| 负载 | 输入长度分布、输出长度、采样参数、并发序列 | 生成脚本 + 固定随机种子 | 至少三级并发 |
| 测量 | 预热请求数、正式请求数、超时、分位数算法 | 压测配置 + 原始结果 | 每格可回溯 |

实验矩阵先写成表，不要边跑边加条件。建议最少覆盖以下格子：

| 实验 | 固定 | 变化 | 回答的问题 |
|---|---|---|---|
| E1 基线 | 模型、负载、引擎 | 硬件平台 | 同条件性能差多少 |
| E2 并发扫描 | 模型、负载、硬件 | 并发级数 | 拐点和饱和段在哪 |
| E3 精度回归 | 评测集、采样参数 | 硬件平台 | 质量差异是否超出容差 |
| E4 算子归因 | 版本、负载 | profiler 采集平台 | 时间花在哪些算子、是否回退 |
| E5 单点优化 | 其它条件 | 一个优化开关 | 端到端是否真的变快 |

“同条件”不是只写同一模型名。输入输出长度、并发模型、流式开关、tokenizer、采样参数、预热与超时都必须一致；只要有一项不同，表里就要标出。条件不同的两个数字可以并列展示，但不能直接相减后宣称“提升 X%”。

## 数据契约

每个结果都要有一行可追溯的记录。推荐把记录编号写成 `平台-实验-并发-重复号`，例如 `nvidia-E2-c64-r1`。原始文件、汇总表和报告正文都引用同一个编号。

| 字段 | 含义 | 缺失时怎么办 |
|---|---|---|
| `test_id` | 实验与并发档位 | 没有编号的结果不进入报告 |
| `run_id` | 第几次重复 | 单次运行标 `r1`，不得伪装成多次 |
| `status` | `measured` / `pending` / `failed` / `invalid` | 不得把 `pending` 填成数字 |
| `conditions_id` | 指向环境、模型、负载配置 | 缺条件的结果只能进附录，不能进主结论 |
| `raw_path` | 原始 JSON/CSV 路径 | 表格里的每个数必须能回溯 |
| `requests` | 总请求、成功、失败、超时 | 分母不清的吞吐不得报 |
| `ttft_ms` | p50 / p95 / p99 与样本量 | 样本量不足时注明 |
| `itl_ms` | p50 / p95 / p99 与样本量 | 与 TTFT 分开报 |
| `throughput` | 单位、时间窗口、成功口径 | 同时写请求/秒或 token/秒，不能混 |
| `accuracy` | 评测集、指标、样本量、容差 | 精度未测就写待补测 |
| `evidence` | 日志、profiler、提交或截图路径 | 没有证据的归因写“假设” |

报告正文只能引用表格中的数据行。若同一行有重复运行，先在数据层计算分布与离散程度，再决定报中位数还是报区间；不要把三次运行里最好的一次当唯一结果。

## 证据等级与归因

把“来自哪里”写清楚，比把结论写得肯定更重要。

| 等级 | 证据 | 可以怎么写 |
|---|---|---|
| A | 同条件、多次运行的原始数据与日志 | “在本实验条件下，测得……” |
| B | 同条件单次运行，或链路完整但重复不足 | “单次测得……，重复性待补测” |
| C | 厂商资料、论文宣称、别人报告的二手数字 | “来源 X 宣称……”并列出来源与条件 |
| D | 估算、推断、未运行 | “估算/假设……，待补测” |
| X | 测量口径不一致或不可复现 | 不用于性能结论，只记录原因 |

归因要从证据走到机制，不能从“国产芯片更慢”直接跳到“算子覆盖差”。一条完整的归因至少包含：

1. **现象**：哪个实验、哪一档并发、哪个指标差了。
2. **定位**：profiler 里哪个算子、哪个阶段、哪类访存或通信占比异常。
3. **机制**：回退到 CPU？缺少融合？KV 分配不同？调度参数不同？网络路径不同？
4. **对照**：关掉或替换该因素后，差异是否缩小。
5. **边界**：这个解释只在什么模型、长度、版本和并发范围内成立。

找不到第 4 步时，结论只能写“相关，未确认因果”。论文或仓库报告里的数字只能当 C 级证据，且必须注明它是作者在另一套条件下得到的；不要改写成“我们在本机实测”。

## 交付结构与验收门槛

报告按下面顺序写，每一节都要能指向数据或命令：

1. **摘要**：一句问题、一句结论、三个关键数字；没有实测就明确写“框架阶段”。
2. **实验设置**：条件表、环境版本、模型与权重、负载生成方式。
3. **结果**：TTFT/ITL 分位数、吞吐、成功数、显存、精度；每张表附数据编号。
4. **差异分析**：算子覆盖矩阵、profiler 证据、回退与通信路径。
5. **优化记录**：改了什么、预期、实测、失败原因；包括负面结果。
6. **复现步骤**：从空环境到出数的命令序列，含校验和清理。
7. **局限与待补测**：没测的、测不了的、只跑一次的、口径不一致的，分开列。

验收门槛：

- 主报告里的每个性能数字都能追到 `raw_path` 和 `conditions_id`。
- 至少三级并发，且报告覆盖同步基线、拐点附近和拐点之后的一段。
- TTFT 与 ITL 分开报，延迟报 p50/p95/p99 与样本量。
- 每个“优化有效”的结论有 before/after 同条件数据；没有就改成“待验证”。
- 两套硬件的精度结果使用同一评测集、同一指标和同一采样参数。
- 报告能指出至少一项证据不足的结论，并说明还需要什么实验。
- 未测项状态明确，不能用旧版本数字或其它负载数字替代。

## 风险与待补测

跨芯片项目最常见的失败是跑出了不可比的数；跑不出数反而更容易被发现。开始前把风险写进项目记录：

| 风险 | 早期信号 | 处理 |
|---|---|---|
| 版本不兼容 | 安装成功后启动失败、算子静默回退 | 固定版本清单；先跑冒烟，再跑性能 |
| 负载不一致 | 两边输入/输出长度分布不同 | 用同一生成脚本和随机种子 |
| 测量不可比 | 一边流式、一边非流式；超时设置不同 | 对齐实验矩阵，记录差异 |
| 精度口径不同 | 评测集版本、prompt 模板或采样参数不同 | 固定模板与版本，保存评测输入 |
| 只跑一次 | 波动大于组间差异 | 至少重复多次；报区间或中位数 |
| 归因过度 | 只看到 profiler 占比就下结论 | 追问机制并做一次对照实验 |
| 缺少国产环境 | 只有一个月试用或借用时段 | 先完成框架、脚本和 NVIDIA 基线；国产侧标待补测 |
| 数据不可追溯 | 表格数字找不到来源文件 | 没有 `test_id` 的结果不进正文 |

把“待补测”写成带触发条件的任务。每条至少包含：缺什么环境、补哪一格、用什么脚本、验收标准是什么。例如“Ascend E2 的 128 并发档待补测：需 CANN 与插件版本锁定后的单节点环境，跑同一 `load.json`，至少 3 次，记录 raw JSON”。只写“以后补”没有执行价值。

- [ ] 两套硬件使用同一评测集、同一输入输出长度和同一采样参数
- [ ] 至少三级并发，覆盖同步基线、拐点与拐点后
