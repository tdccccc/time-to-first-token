# M4 · 综合项目：跨芯片推理优化报告

> **状态**：占位页。目标、前置、交付物和检查清单已确定；逐周教程与实测数据待补。

## 这个模块要做什么

同一模型、同一评测集，在 NVIDIA GPU 与至少一种国产芯片上各跑一遍端到端推理服务，记录可复现的环境、命令、指标和差异，写成一份别人能照着复现的报告。这是整条路线的毕业设计，也是 M2/M3 的收口。

它不要求你提出新算法。它要求你把**同一件事在两套硬件上做两遍**，并且诚实地区分：哪些差异来自算子覆盖，哪些来自调度/显存，哪些只是版本或环境不同。

## 前置

- **M0**：会用 Roofline 算账，能写压测脚本、填一份基线报告。
- **M1**：部署过 vLLM 或 SGLang，知道 TTFT、ITL、吞吐和 p99 怎么测。
- **M2 / M3**：至少完成一个自写 kernel，或在 Ascend 上跑通过一次推理服务。

没有国产芯片卡也可以先做计划和骨架；实测部分标「待补测」，等有环境再填。不要用估算数冒充实测数。

## 交付物

1. **报告正文**（Markdown 或 PDF），结构见下节。
2. **可复现的材料**：环境版本表、启动命令、压测命令、配置文件和原始结果（JSON/CSV）。
3. **一页选型结论**：在什么负载、什么预算下选哪套硬件/引擎，边界条件写清楚。
4. **一份负面结果**：至少记录一个「优化了但没变快」或「换了硬件但没达到预期」的案例，并分析原因。

## 建议的 6 周安排

| 周 | 主题 | 产出 |
|---|---|---|
| 1 | 选题与评测集 | 固定模型、输入长度分布、并发档位和验收口径；一页实验计划 |
| 2 | 环境与基线 | 两套硬件各自跑通，记录驱动/SDK/引擎版本；同条件基线表 |
| 3 | 性能对比 | TTFT / ITL / 吞吐 / p99，至少三级并发；曲线和原始数据 |
| 4 | 差异归因 | 算子覆盖矩阵、profiler 证据、回退路径；归因表 |
| 5 | 优化一轮 | 至少一个有效优化 + 一个负面结果；before/after 对照 |
| 6 | 写作与复现 | 报告终稿、脚本、原始数据；让别人按文档能跑一遍 |

## 报告结构

1. **摘要**：一句话结论 + 三个关键数字。
2. **实验设置**：硬件、驱动、SDK、引擎版本、模型权重、评测集、并发档位。
3. **结果**：TTFT/ITL 的 p50/p95/p99、吞吐、显存、成本；图和表都要有原始数据来源。
4. **差异分析**：算子覆盖、调度、显存、通信；每一个结论对应一条证据。
5. **优化记录**：改了什么、预期是什么、实测是什么、为什么。
6. **复现步骤**：从零到出数的命令清单，按顺序可复制。
7. **局限与待补测**：没测的、测不了的、只测了一次的，分开写。

## 检查清单

- [ ] 模型、权重、引擎、驱动版本全部固定并记录
- [ ] 两套硬件使用同一评测集、同一输入长度分布
- [ ] 至少三级并发，报告 p50/p95/p99，不只报平均值
- [ ] TTFT 与 ITL 分开报，prefill 与 decode 不混成一个数
- [ ] 原始 JSON/CSV 保留，表格里的每个数都能回溯
- [ ] 启动和压测命令可直接复制，不依赖口头补充
- [ ] 未测项标「待补测」，没有编造的数字
- [ ] 选型结论写清边界条件，不写成无条件推荐
