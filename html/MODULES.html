模块地图 M0–M4

本仓库是一份中文 AI Infra 推理优化学习计划，以 M1 的 10 周路线图为主线，前后各加模块，构成一条从“会看系统”到“跨芯片对比”的完整路径。所有模块共用 M0 的压测脚本和基线报告格式，数字之间可以互相比较。

模块 内容 产出 前置 状态
M0 · 基础与度量 Roofline、TTFT/ITL/吞吐、profiling、可复现的压测脚本 一份基线报告 + scripts/bench_openai.py 无（不需要 GPU） ✅ 内容已完成
M1 · 推理框架 10 周路线图 + 2 处可选加深（第 8 周（续）、第 11 周 TensorRT-LLM）：vLLM → SGLang → 量化 → 投机解码 → 解耦部署 → 路由器 → 发表（→ TensorRT-LLM，可选） 一个不断长大的 OpenAI 兼容推理服务 + 一份 benchmark 写作 M0 ✅ 内容已完成（中文翻译版 + 第 8 周（续）与第 11 周）

M4 · 综合项目 同一模型 + 同一评测集，在 NVIDIA 与至少一种国产芯片上端到端部署、压测，写出可复现的对比报告 一份完整的、可复现的跨芯片推理优化报告（本仓库的毕业设计） M0–M3 📝 仅有目标，内容待写

建议顺序

M0（1 周，无 GPU 可做）
 → M1（10 周主线 + 第 8 周（续）与第 11 周可选加深）
 → M2（6 周，与 M1 第 6–8 周并行或之后做）
 → M3（6 周，Ascend 环境就绪后做）
 → M4（毕业设计）

M2 与 M1 后半段可以并行：M1 第 6 周讲量化时，正好做 M2 第 4 周的量化 matmul；M1 第 7 周讲投机解码时，可以对照 M2 第 5 周读的 kernel 实现。M3 建议放在 M1 之后，因为它需要你已经会部署、会压测、会读 profiler 输出。

每个模块的共同规则

  • 每节 30 分钟，和 M1 的节奏一致；做不完的留到缓冲日，不要拖长单节。
  • 每节开头标硬件门槛：「无卡可做 / 需云 GPU / 需国产芯片卡」，并给出无卡替代路径。
  • 每节有产出：一张图、一份表、一段能跑的代码、一份报告——没有产出的节不算完成。
  • 不编数字：没测的写“待补测”；国产芯片相关的实测一律按「某年某月某版本实测」的格式记录。
  • 进度跟踪：M1 用 progress.md 或 index.html；M2–M3 用各自模块 README 末尾的检查清单；M4 内容待写，暂无清单。
